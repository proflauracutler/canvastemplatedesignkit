Design Kit - Visual Style Reference

  How to Use This Page

This page is a living style reference, not a real reading. Every component below uses the same color system so all module pages look like they belong to one course. When you want to tweak something (a color, a spacing value, a card style), say so and Claude will update this page first -- once it looks right here, the same change gets applied across the other modules.

Color rule of thumb: Navy is the default. Steel blue, indigo, teal, and gray are the supporting accent colors for cards and variety. Green means "correct / good," and the muted rose/red means "needs work / avoid" -- use that sparingly and only when something is actually a mistake to flag.

Dark mode rule: Anytime an element sets a background or background-color, also set an explicit color in the same style. Canvas's dark mode rewrites text color but not backgrounds, so a light box without an explicit text color turns into light text on a light box and disappears.

  Section Heading Style

Every major section uses this heading style: a Font Awesome icon in a circle, followed by a horizontal line, then the title. Always use navy (#002e5d) for the icon and line color. Only the icon name and the title text change between sections.

Common icons: fa-book-reader (intro/reading), fa-bullseye (purpose/goals), fa-list-ol (instructions/steps), fa-lightbulb (key concepts), fa-chart-bar (data/analysis), fa-comments (discussion), fa-tasks (assignments), fa-paper-plane (submission), fa-check-square (grading), fa-puzzle-piece (synthesis/closing), fa-search (research), fa-sitemap (systems/structure)

  Callout Boxes

Three callout types, used sparingly. Default to the navy "key rule" box for most callouts -- the other two are for genuinely distinct situations.

Key Rule: The default callout. Use for important rules, definitions to remember, or framing statements.

Tip: Use teal for helpful tips, shortcuts, or "in practice" notes that are useful but not essential.

Watch Out: Use the muted rose/red callout only for real warnings -- common mistakes that will cost students points, or steps that are easy to get wrong.

  Multi-Color Cards (Small Groups of Related Items)

Use this layout for any small set of categories, phases, or principles that belong together as a group. The 5 colors below are a single rotation -- cycle through them in order. Navy and gray (both low-saturation neutrals) are placed at opposite ends of the rotation so they never sit side by side. If a framework has more than 5 parts, start the rotation over: item 6 is navy again, item 7 is steel blue again, and so on.

1. Navy

Primary slot. The first item, or the most important one.

2. Steel Blue

A brighter blue that's still distinct from navy.

3. Indigo

A deeper, cooler accent for the third slot.

4. Teal

Adds a touch of color without leaving the cool family.

5. Gray

A true neutral that closes out the rotation before it repeats from navy.

Most frameworks have 3-4 parts, so in practice you'll usually only use colors 1-4 (Navy, Steel Blue, Indigo, Teal). The 5-color rotation exists so that if something has 5+ parts, you have a defined order to follow instead of picking colors ad hoc.

Use for step-by-step assignment instructions. Alternate the background between #f0f4f8 and #ffffff for readability. The circle and left border are always navy.

  Standard Data Table

One shared table style covers step-by-step sequences, side-by-side comparisons, and rubric/grading tables. All of them use: a solid navy header row with white text and matching navy borders, body cells bordered in light blue-gray (#d0dae8), and banding only when there are more than 2 body rows -- alternating #f0f4f8 then #ffffff, starting with #f0f4f8. With 2 or fewer body rows, skip banding and make every row #ffffff.

Item Description
First item Description text for the first row.
Second item Description text for the second row.
Third item Description text for the third row.

Variations on this same table:

  • More columns (comparisons): add more header/cell columns -- e.g., "Aspect / Option A / Option B." Same header, border, and banding rules apply.
  • Centered points column (rubrics): add a "Points" column and center-align both the header and the cells in that column.
  • 2 or fewer body rows: drop the banding -- make every row background: #ffffff; color: #333;.

If there's a summary or conclusion row at the bottom (common for sequences that build to a takeaway), add one final row spanning all columns, styled solid navy with white text:

Conclusion The takeaway the sequence builds toward.

  "Avoid vs. Do This" Comparison Table

Use this when you need to contrast a wrong/weak approach with a correct/strong one (e.g., vague vs. precise requirements). Only the header row carries color -- rose for "Avoid," green for "Do This Instead." With 2 body rows, no banding is used -- both rows share the same uniform background.

Avoid Do This Instead
"Make sure students understand the requirements." "List each requirement as a separate numbered item, with one sentence describing what 'done' looks like for that item."
"Give feedback on the draft." "Identify one specific sentence or section that is unclear, and explain what question it leaves unanswered."

  Code Blocks

For any block of source code, use Canvas's default <pre><code> styling (background, border, and text color all left as-is) and only bump the font size to 16px -- Canvas's default monospace size renders too small.

def greet(name):
    return f"Hello, {name}!"

print(greet("world"))

For a short inline code reference within a sentence, use inline_code() with Canvas's default styling -- no extra background or color needed.

"Try It" Embedded Code Sandbox (Trinket)

Trinket embeds require a saved trinket -- you can't pass arbitrary code through the URL. To create one: go to trinket.io, start a new trinket in the language you need, write and save the starter code, then click Embed (or Share > Embed) and copy the URL it gives you. It will look like https://trinket.io/embed/python3/<trinket-id>. Paste that into the src attribute below.

Instructions here -- describe what the student should change and run.

showInstructions=true shows any instructions text saved with the trinket; start=result runs the program automatically when the embed loads. Adjust height based on how much output the program produces (250-400px is typical).
